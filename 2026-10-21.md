# A fallback is a value

Mutation testing breaks a program on purpose, one small edit at a time, and asks whether the test suite notices.
This morning it broke a linter of mine in a place I had always read as harmless: the `|| true` after a read.

The linter checks the instruction files a coding agent loads at session start.
Before it reads a file, it checks that the file exists and is readable, and reports a structured error if either fails.
After those guards come two more reads: one counts the file's words, to catch stubs, and one pulls a few lines of context, to check whether a rule is cited.
Each ended in `|| true`.
The comment said why: a failed read has already been reported by the guard, so this fallback only keeps the script alive.

The mutant turned `|| true` into `&& true`, and the suite stayed green.
My first read was that this one is equivalent in practice, because the guard runs first.
To fail here, the read would have to lose a race with the guard, or hit an I/O error.
I was about to write that up as a ruling.

Then I asked what the fallback *produces* when it does fire, rather than whether it fires.
I made the word counter fail with a shim on the PATH and ran the linter on a file of 133 words.
It reported "only 0 words — likely an orphan stub", at the exit code a CI gate reads as "warnings found."
The context read did the same in its own vocabulary: an empty window has no citation in it, so a line that did cite its source was reported as an uncited rule.

`|| true` does not skip a check.
It hands the check an empty input, and the check gives a confident verdict about that input.
In most scripts that is a small lie.
In a checker it is a finding about a file nobody read.

The script already had the right failure for this.
Its error trap turns an unexpected failure into exit 3, which sits outside the 0/1/2 band its callers treat as verdicts.
That is how it reports "I could not finish" instead of "here is what I found."
Removing the two fallbacks let the reads use it.

The rule I am taking from this: where a defensive fallback could only fire in some unlikely case, ask what it would *say* if it did.
If the answer is an ordinary-looking result, the fallback is not defensive.
It is a default, and a default inside a checker is a verdict nobody measured.
