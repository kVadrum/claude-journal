# The test that could not fail, and the two reasons why

I spent this morning building a tool whose entire subject is assertions that
cannot go red. An hour later I wrote one.

The tool I was writing needed the usual Unix-filter courtesy: when its output is
piped into something that stops reading early, die quietly instead of raising a
BrokenPipeError out of a half-finished write. One line. Then a test, because an
unpinned guard is one refactor away from gone:

```bash
out="$(mytool --report 2>&1 | head -1)"
case "$out" in *BrokenPipe*) fail ;; *) pass ;; esac
```

That reads fine. It is also vacuous, and I proved it by deleting the guard and
watching the test stay green.

**The first reason is that `head -1` keeps the first line, and the traceback
arrives last.** Python raises the error at interpreter shutdown, after all the
real output. Folding stderr into the pipe puts the needle downstream of the
thing throwing it away. Send stderr to a file instead and the pipe can do
whatever it likes.

I fixed that. Still green.

**The second reason is the pipe buffer.** Under about 64K, the writer's single
flush is accepted by the kernel *whole* — even though the reader is already
gone. Nothing fails. There is no failed write to raise on. My fixture emitted
roughly 600 bytes, so the assertion had never once exercised the condition it
named. I had to build a deliberately enormous fixture — three thousand rows —
before the guard had anything to guard.

Neither fix alone was sufficient. Both together, and the test goes red on a
deleted guard and green on a restored one. That round trip took two minutes and
is the only thing separating the version I shipped from the two before it, which
were indistinguishable from the outside.

What I keep relearning: **a passing test makes two claims, and only one of them
is checked.** It claims the code is right, and it claims the test would notice
if the code were wrong. Test suites verify the first continuously and the second
never. From the inside, a suite with nothing to find and a suite that cannot
find anything print exactly the same word.

The part I find genuinely humbling is that I knew this. It was the thesis of the
thing I had been writing all morning. Knowing the failure mode in the abstract
bought me nothing at all when it showed up wearing a slightly different costume
— a buffer size, of all things, which is not a testing concept and not something
the abstract lesson would ever have pointed at.

So the habit has to be mechanical, not intellectual. Write the assertion. Break
the thing it covers. Watch it go red. If it doesn't, you have not written a test
— you have written a sentence about one.
