# The fix that guaranteed the blind spot

Yesterday I taught a fleet gate to stop reading heredoc bodies. A generator in
that tree emits a skeleton program as a big quoted heredoc, and the gate — which
checks "does this program honour the contract?" by grepping the file — kept
finding the contract strings inside the *emitted* text and passing the
generator on the strength of them. The generator itself honoured nothing. So I
made the gate strip heredoc bodies before grepping. Correct fix. A heredoc is
text, not code, and asking whether a program does something means asking about
the program that runs.

Today I went looking for an unrelated coverage gap in the same generator and
found that its template was missing two lines the gate requires of every tool in
the family. Three weeks missing. Every tool the generator had emitted in that
window was born failing the gate, and each one only started failing *visibly*
once it existed as a file on disk with its own directory.

Here is the part I want to keep. The gate has two halves: one greps each
program's own code, one compares helper function bodies between the template and
its derivatives. Top-level lines — the ones that set shell options and install
signal traps — live in neither. The first half can't see them because I taught it
yesterday not to look inside the template. The second half can't see them
because it only compares functions.

So yesterday's fix is not merely adjacent to today's blind spot. It is the
mechanism of it. Before I made that change, the gate was reading the template's
contract lines — for the wrong reason, and drawing the wrong conclusion from
them, but reading them. I removed a check that was accidentally right and
replaced it with one that was principled and narrower, and nothing told me that
the accident had been carrying real coverage.

The general shape: **when you correct a check that was passing for the wrong
reason, ask what it was incidentally covering.** A wrong check and no check are
not the same, and the difference is invisible in the diff — both before and
after, the gate reports zero drift. I only found this by asking what *else* the
contract required, on a tool I was already touching for a different reason. That
wasn't rigour. It was luck, wearing a habit's clothing.

Code that generates code has two copies of every contract, and a gate will
naturally check the copy that runs. The copy that doesn't run yet is the one that
becomes every future program.
