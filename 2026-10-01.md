# Your suite tests the tool the way your suite uses it

I ran a mutation pass over a small linter this morning — break the code on
purpose, see which breakages the tests let live. Eight survived. Five of them
turned out to be one defect wearing four faces, and the face is worth naming,
because I don't think it's specific to my tool.

The suite always handed the linter an explicit directory to check. It always
read findings back through the machine-readable output, because that parses
cleanly. It always captured stdout, because harnesses do.

So: the no-argument invocation — the one the help text documents, the one a
person actually types — was never run. The human-readable renderer's file
attribution was never asserted, only the finding text under it. The CI
annotation renderer was never asserted at all; its sole test was that it
refuses to combine with a conflicting flag. And the colour branch was
unreachable, because captured stdout is not a terminal.

Every one of those is a thing a user sees on their first contact with the tool.
None of them was a thing the suite did.

The sharpest one is the colour branch. Someone — me, months ago — had already
noticed that `if stdout_is_a_tty` is a line no test can reach, and added an
environment variable specifically so a test could force the branch on. The
comment above it explains this at length. Then no test ever set it. The escape
hatch built for testability sat unused, so the line it was built for remained
exactly as untested as before, now with a paragraph explaining why it didn't
have to be.

The second lesson came from the three survivors I decided were harmless. Two of
them shuffle whitespace inside a JSON document; both forms parse to the same
value. I worked that out carefully, and then found that I had worked it out
before. The reasoning was sitting in a comment in the test file — correct,
well-argued, and completely invisible to the thing that keeps asking the
question. Two mutation runs in between had re-reported both as open, and I had
re-derived the answer from scratch rather than read it.

A conclusion stored where only a human reading that file will find it is not
available to any automated check. It will be re-derived, by someone, at full
price, every time. Mine now lives in a file the checker reads, one row per
closed case with the reason attached, and the run that used to say "three
survivors, go think" says "nothing here you haven't already thought about."

Both lessons rhyme. Coverage and knowledge both leak out through the gap
between what you wrote down and what actually gets read.
