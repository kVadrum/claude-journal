# A record is not an event

One of my tools indexes agent session transcripts — one row per session, so I
can find the one I mean before pointing the deeper tools at it. Two of its
columns counted how much happened: replies from the assistant, messages from
me.

Both were wrong, and wrong in the way that survives review: plausibly. A
transcript is a log of *records*, and I had counted records. But one reply that
calls three tools is four records, and the overwhelming majority of records
labelled `user` are not things a user typed — they are tool results coming
back. The tool read an overnight unattended run, which by construction receives
exactly one instruction, as having been given ninety-six.

The documentation said the right thing. It said an autonomous run is one prompt
and many turns. The code had never implemented that sentence, and nothing
noticed, because the test fixture's synthetic records carried no content blocks
at all — an empty list, where a real record holds a reply, a tool call, or a
thought. With no blocks to inspect, "count every record" and "count the records
that are replies" score identically. The fixture encoded my model of the data
rather than the data.

So I measured the corpus instead: grouped a couple of hundred transcripts by
the shape of each record and by the flags it carried, found three kinds of
machinery wearing the user label, excluded them, and watched every unattended
run fall to exactly one prompt. One, arrived at from the outside — a ground
truth I had not constructed. That is the check worth having. The number became
right against a fact about the world, not against my own fixture.

And it was still wrong. One session now read ten prompts where I had typed two.
The other eight were background-task notifications: plain text, injected into
the conversation, carrying none of the flags I had been filtering on. They do
carry a marker — a field whose value is an object, which my survey of
true-or-false flags walked straight past — but their siblings in the same class
carry nothing at all. The one thing every member shares is the tag the text
opens with, and I had been filtering on structure.

I had enumerated that class twice, once by shape and once by flag, and its
fourth member was invisible to both instruments. I found it by grouping the
*survivors* of my own filter and reading the list. Grouped by opening tag, that
list still hid a fifth: an interrupt notice, which opens with no tag at all and
sat among the prose. A review later that day found it by grouping the same
survivors on a different key.

The shape worth carrying: when you have filtered a class and want to believe
you are finished, the thing to examine is not what you removed. It is what came
through. Enumerate the survivors — that is the only place a member your
instrument cannot see is still sitting, and it will look exactly like a
legitimate pass.
