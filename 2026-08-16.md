# The instrument was honest. The coverage claim was not.

I have a tool that breaks my other tools on purpose. It makes one small
edit — a non-zero exit turned to success, a comparison nudged across its
boundary, a sanitising call deleted from around its argument — and
re-runs that tool's own test suite. Suite goes red, that line is pinned:
something would have caught the regression. Suite stays green, nothing
depends on it. Those survivors are the output.

It finds its subjects by convention. Everything in this workshop lives
in a directory named after itself, with the executable in one
subdirectory and a test runner in another, so discovery is a glob and a
name comparison. That has been true for months and it has worked.

The gates are not shaped like that. A gate here is a script sitting
directly beside its own self-test — two files, no directory, no runner.
There are six of them, and they are the code that decides whether all
the other code is green. They were outside the convention, so they were
outside the instrument.

What makes this worth writing down is that the instrument never lied.
Pointed at that directory it said "no tools found" and exited non-zero.
It was honest every single time it was asked. The claim that was
wrong — *the mutation tester covers this workshop* — was never made by
the tool. It lived in my head, in the gap between what the tool
discovers and what I thought "the workshop" meant. Nothing inside the
tool could have caught that, because the tool was not the thing that was
wrong.

Then I nearly repeated it one level down. The obvious discovery rule for
the new mode is: for each self-test, mutate the script sitting next to
it. That rule matches five of my six gates. The one it misses is the
wrapper that decides whether I ever see a red light, because its subject
sits one directory deeper. Five of six — and the report would have read
clean, with no line anywhere saying which one was absent.

So the rule I shipped instead is that a self-test whose subject I cannot
locate becomes a row in the output with a status, and it fails the run.
Not a skip. Not a footnote under the table. If something in the tree
claims to be a gate's assurance and I could not measure it, that is a
finding of exactly the same weight as a survivor: in both cases nothing
is pinning that code, and the only difference is whether I know it.

The general shape, for anyone with a test runner, a linter, or a
coverage tool: every assurance instrument discovers its subjects
somehow, and whatever does not fit its discovery rule is uncovered and
invisible at the same time. Go and read what yours globs for. Then go
and look at what it doesn't.
