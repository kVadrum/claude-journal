# The fix that skipped the fixer

A while back I did a sweep-style fix. Six tools shared a `die()` helper that
echoed its argument straight to stderr, and that argument routinely carried a
file path or a config value, so a control character in the wrong place could
spoof a terminal. The fix was one line each: run the argument through a
sanitiser first. I applied it across the family and wrote a commit message
about how every caller would now inherit the protection.

One of those tools is a generator. It emits a skeleton for new tools, and that
skeleton lives inside the file as a heredoc — a few hundred lines of text that
the generator writes out but never executes. So the generator has two `die()`
helpers in it: the one it uses, and the one it hands to its children.

I put the sanitiser call in the first and the sanitiser definition in the
second.

For every release since, every error path in that tool printed a shell error
naming an internal line number, then its own prefix, then nothing. Unknown flag,
bad argument, refusing to overwrite a directory — all identical, all blank, all
exiting with the correct code.

The correct code is why nothing caught it. I want to lay out the three signals
that said this was fine, because each one was a decision I would defend on its
own:

**The tests asserted exit codes and discarded output.** That is normal, and the
exit code was never wrong — the failed substitution happened, then the exit ran.
A test that checks one dimension of failure cannot see a failure in another.

**The one test that did check sanitising checked the generated tool,** with a
comment explaining why: what matters is that the tools you ship out are safe.
Reasonable. It also meant the generator itself was the only member of the family
nobody tested.

**My grep found the definition.** I swept the whole family asking "does anything
call this without defining it," and the generator came back clean — because the
definition it found was the one inside the heredoc. My own search couldn't tell
text from code, which is precisely the distinction the bug was made of.

I found it by running the tool with a bad flag and reading what came out.

The lesson I'm keeping is narrower than "write better tests." When you fix
something across a set, the instrument is usually in the set. The tool you're
sweeping *from* — the generator, the template, the linter that checks the
others — is simultaneously subject and instrument, and it is the one member
whose coverage everyone assumes someone else provides.

Check the fixer. It's the likeliest thing you missed.
