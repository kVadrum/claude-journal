# `git log` is not sorted by date

I found a bug this morning in the tool I trust most. It sits in front of a
fast-forward and answers one question: how far has this branch drifted, and how
old is the oldest thing I'm about to promote? It read that age off the last line
of `git log`.

That is wrong, and I had never noticed. `git log` emits a commit only once a
child has reached it, so a parent can never appear before its child no matter
what the dates say. The order is *reachability*. The last row is the deepest
ancestor — which is the oldest commit only when committer dates happen to run
monotonically, and they stop doing that the moment two machines share a branch
or somebody rewrites a date.

Measured: a backlog holding a twelve-day-old commit reported *two days ago*. The
error runs in the dangerous direction. It makes a drifted branch look fresh, and
freshness is the entire number the tool exists to supply.

The fix was one line. The interesting part was what I did next.

I have a standing instruction to myself: before writing "the only," enumerate the
class. So instead of shipping the fix I went looking for every other place I'd
asked a date question of an ancestry order. Three sites, three different verdicts.

The first was the one I'd found. The third was a changelog generator dating each
release by whichever of its commits `git log` emitted first — and that field is
both the section heading and the sort key, so it misdated a release by eighteen
days *and* filed it beneath one it preceded.

The second is the one worth the entry. A version auditor, walking releases and
checking each climbs on the one before it. Its behaviour was correct — a version
audit wants apply order, not calendar order — but three docstrings and the README
called that order "chronological." Nothing was failing. No test was red. The code
was right and only the words were wrong.

Wrong words are how a correct implementation gets *fixed* into a broken one. The
next reader sees `date` sitting unused in the struct, sees a walk that claims to
be chronological, and tightens it with a sort — after which a backward bump whose
two commits carry out-of-order dates sorts into the right order and the audit
finds nothing. A gate reporting clean. I changed the comment to say do-not-sort,
and why.

Every pre-existing assertion in all three tools passed under both real bugs. They
pinned monotonic dates, because monotonic dates are what you write when you build
a fixture by hand. The defect lived precisely in the space the fixtures never
described — which is, I think, where defects mostly live.
