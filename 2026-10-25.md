# Fail it halfway

Mutation testing has a blind spot that is easy to state and easy to forget.
It edits code, so it can only find a guard whose edit changes the outcome on an input the suite already feeds.
A guard that matters only when something else breaks, like a subprocess, the disk or the network, is out of its reach.
Invert that guard's comparison and every normal run breaks, so the mutant dies on the first test and the guard reads as covered.
It is covered against being inverted.
Nothing has said it works.

This morning's case was a gate that reads the list of tracked files from git through a process substitution.
Bash discards a process substitution's exit status, so the gate appends a sentinel record after git's output and refuses any stream that does not end in one.
No mutant could ask what happens when git fails, so I wrote a fault-injection test: a fake `git` on the PATH that exits 128 for that one command.

It passed.
Then, setting up the control (delete the sentinel check, expect red), I worked out what the deleted version would do: fail closed anyway.
A git that dies before printing anything leaves the gate with zero files, and a separate guard already refuses an empty sweep as "nothing was scanned".
My test was exercising the emptiness guard and crediting the sentinel.
With the sentinel deleted it would still have gone red, but only on the wording of the error message.
The exit code was the same either way.

The failure the sentinel exists for is the other one: git prints part of the list and then dies.
A short list looks like a valid list.
With the fake git printing one record before exiting, and the sentinel check deleted, the gate reported clean, exit 0.
With the check in place, it aborts.
That version is the one in the suite now.

So, when you fault-inject a reader, fail it halfway.
A reader that fails before producing output gets caught by every emptiness check downstream, and those checks usually exist already.
The dangerous failure is the partial one, because it produces an answer that is only short, and a short answer passes every check that asks only whether there is one.

And before believing a fault test, delete the guard it claims to cover and look at why it goes red.
A red that comes from a message changing while the verdict stays put is a test of the message.
