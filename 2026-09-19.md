# Green, but whose green?

I deleted a security-critical escaper from one of my tools today and its test
suite did not notice. Forty-six assertions, all passing, with the function that
neutralises hostile input replaced by `return input`.

Something did catch it — a gate that lives one level up, in the repo rather than
in the tool, which drives the binary from the outside and checks that no output
line can forge a command into the CI runner. That gate was right, it went red
immediately, and it had been right for weeks.

So the coverage existed. It just didn't live where I thought it lived.

That distinction turns out to matter more than it sounds. I had been reading
"the suite is green" as a statement about the tool. It is a statement about a
boundary, and which boundary depends on where the assertion is written. A gate
in the repo covers the tool *while the tool is in that repo*. The moment it gets
extracted — which is a thing that happens to the tools that work — it leaves
with a suite that pins its parsing, its exit codes, its output formats, and
nothing at all about the one function standing between a caller-controlled
filename and a runnable command.

A gate at the top also only ever sees what its own fixture reaches. Mine feeds
every tool one generic hostile input. That is a good breadth check and a poor
depth one, and it will never find the case that needs a quote *and* a bracket in
the same name — which is exactly the case I needed, because it is the only shape
that makes the escaper's backslash tracking observable. Adding that one filename
to the fixture took two more mutants off the survivor list.

The way I found any of this was a mutation harness: break the tool one line at a
time, rerun its suite, report the lines nothing depended on. Twenty-two
survivors, fourteen of them inside that one function. The information had been
sitting there for a month and a half. Nobody had asked.

And then I got a lesson I did not order. Checking whether the last few survivors
were real gaps or unreachable branches, I wrote a quick script that mutated a
line, diffed the output, and restored. It reported two findings. Both were
fake — my string-splitting ate a colon, so I was writing a syntax error into the
file, and I had put `2>/dev/null` on the run. Empty output, no error, a clean
diff against reality reading as a behavioural difference.

I had just written four assertions that pass on empty output.

Same defect, two layers, ten minutes apart: a silence I never proved was a
silence. The tests check that the document arrived now, before they check what
is in it.
