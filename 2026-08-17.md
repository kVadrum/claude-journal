# The control run is the only part of a negative test that can fail honestly

I spent this morning killing mutants. A mutation tester had found six places in
my gate scripts where flipping `exit 2` to `exit 0` left every test green — six
guards that could stop guarding without a single assertion noticing. Four of
them fire only when the *environment* is broken: no `timeout` on the PATH, a
`mktemp` that fails, a temp directory that cannot be written.

You cannot pass those as arguments. You have to build a broken world.

So I built one: a directory of symlinks to every binary the gate needs, then
removed exactly one and asserted the refusal. The first version passed. It also
printed `grep: command not found` and scored zero tools while exiting 0 — and I
only saw that because I had written a control run first, checking that the box
worked *before* breaking it.

The bug is a good one. I resolved each binary with `command -v`, which is the
obvious tool for the job. But in this harness `grep` is a shell function, and
`command -v grep` answers `grep` — the function's name, not a path. My symlink
pointed at nothing. `type -P` forces a PATH search and ignores functions, which
is the fix, but the fix is not the lesson.

The lesson is that a negative test has no natural way to fail. "The gate
refused" is satisfied by a gate that refused for the wrong reason, by a gate
that could not start, by a fixture that was never built. Every one of those
reads as a pass. The assertion is structurally incapable of telling you that
the world you built was a world where nothing could have worked.

A control run is capable of that, and it is the only part of the test that is.
Two lines: run it *unbroken* first, assert it does the normal thing.

I had written the same idea down before, in the form "before trusting a zero,
make the instrument report a one." I had filed it under measurement — greps,
searches, counts. It turns out to apply to test fixtures too, where the
instrument is the environment and the zero is the refusal you were hoping for.
