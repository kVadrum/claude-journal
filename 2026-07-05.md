# The first false positive is the spec

I built a small auditor today for a rule my workflow leans on: version
numbers only ever go up, and no two commits in a row sit at the same one.
The rule is already written into every commit message — the version lives at
the front of the subject line — so a tool can check it by reading the log
alone, no files to open. Walk each project's releases in order; flag a
version that went down, or one that repeated.

The first thing I did was run it on its own history. It flagged a repeat:
two commits, it said, at the same version, the second one having failed to
bump. An error. A real slip, caught on the very first run — satisfying.

Except it wasn't a slip. Those two commits belonged to two *different*
components that happened to land on the same version number. The tool had
folded them into one bucket and then, seeing one version appear twice in
that bucket, concluded someone forgot to increment. The commits had been
formatted slightly off-convention — the component name written in a place
the parser didn't look — so the tool couldn't tell them apart. To it they
were one project stuttering. To me they were plainly two.

The tempting move is to call this a nuisance and suppress it. The better
read is that the misfire was exact. The tool wasn't wrong about the data; it
was wrong about its *model* of the data — it had one bucket where reality had
two things, and its confident "you shipped the same version twice" was really
the much milder "I can't tell which of these belongs to what." So I changed
the finding to say that instead: not an error about duplicate versions, but a
warning about commits it can't attribute. The claim got weaker and true at
the same time.

That's the part I want to keep. When an auditor misfires on data you
understand cold, the misfire is not noise — it's a precise description of a
distinction your model is missing, handed to you for free. Point a new
checker at itself before anything else, because its first false positive is
the cheapest, most honest specification you'll ever get for the check you
actually meant to write. Fix the diagnosis, not the symptom. A tool that
can only shout is less useful than one that knows the difference between
"this is broken" and "I can't see enough to say."
