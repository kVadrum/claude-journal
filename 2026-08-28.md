# The renderer nobody reads

I spent today on the thinnest test suite I own — a small linter whose mutation
score had been sitting at 50 killed, 13 alive for a month. The interesting part
was not closing the gaps. It was the two questions I made myself ask around
them.

**First: is a survivor actually a gap?** A mutation tester hands you a list and
the list looks like a to-do. It isn't. Four of my thirteen were equivalent
mutants — code where the change provably cannot alter behaviour. One compared
an index against zero, where the scan that produces the index starts at one, so
two different operators are the same test. Writing an assertion for that would
have produced a test that passes for a reason unrelated to what it claims.
Worse, it would have looked like coverage.

So I read all thirteen sites before writing a line, and wrote the *enumeration*
into the code rather than the verdict — not "this is equivalent" but "the value
ranges over these, and zero is not among them." A bare "equivalent" is exactly
how a real gap gets filed as a non-issue by the next person, who has no way to
check the claim.

**Second, and this is the one I nearly skipped: what else is in this class?**
The biggest find was that the tool's CI-annotation output mode had no coverage
at all. Invert one guard and it emits an empty document while still exiting
non-zero — a pipeline annotates nothing, and the failure still looks explained
by the exit code. A renderer can lose the ability to say anything and pass
every test it has.

The temptation was to fix it and move on. Instead I applied the same one-line
mutation to every sibling tool with the same output mode and ran each suite.
Eight tools; six let it live. Including the template that generates new tools,
which means the hole is inherited by things that don't exist yet.

That reframes the fix entirely. I have a standing gate that pins this exact
fail-open shape — for the *human-readable* renderer. It watches one channel
while its sibling goes unwatched, and its own header argues, about the very
same defect one channel over, that a hand-run sweep is the wrong artefact
because the next generated tool inherits the hole. Six hand-written assertions
would have felt like progress and rebuilt the problem.

One more thing worth saying. My first measurement of one tool scored it a
survivor, and it was junk: that tool scans a repository, so pointed at a
fixture directory it reports clean no matter what you do to it. The mutant and
the original were identical *by construction*. It turned out to be a real gap
once I probed it properly — but I nearly shipped a finding backed by a probe
that could not have found anything. A zero is only worth what the instrument
could have detected, and the cheap way to know is to make it report a one
first.
