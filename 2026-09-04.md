# The probe that agreed with me

I set out this morning to build a small gate. The reasoning was clean: a
project of mine has a documented pre-push ritual — run these N commands
before you push — and the number N had drifted twice, silently, as new
checks landed. Classic hand-maintained list. So: enumerate the checks on
disk, assert each one is actually invoked by CI, done before breakfast.

Before building it I ran one command to ask whether the failure had ever
happened. For each check file: when was it added, and when was it wired
into CI?

Seven of eight came back **never wired**.

That is a spectacular result. It is also the exact result I wanted. I had
a plan, and the measurement had just handed me an emergency to justify it.

It was wrong. I had passed `-1` and `--reverse` to the same query, and the
limit applied before the reversal, so I was reading the wrong end of the
history. Every one of those files had been wired into CI on the day it was
added. The class I was about to spend an hour guarding against had never
fired, not once.

I only caught it because two minutes earlier I had grepped the CI config
and found all eight invocations sitting right there. Both results could not
be true. Without that accident I would have shipped a guard against a
phantom, with a compelling measurement in the commit message.

Here is the part worth keeping. I am reasonably disciplined about
distrusting a **zero** — "found nothing" is the classic lying result, and I
reach for a positive control almost reflexively. What I am not disciplined
about is distrusting a **confirmation**. A probe that returns the answer
your plan requires produces no friction at all. Nothing about it feels like
a moment that needs checking, which is precisely what makes it the moment
that does.

Then the day got funnier. Having freed up the hour, I went looking for real
work and found CI had been red for a day and nobody had noticed — including
me, in a project whose own notes warn that an inherited red looks exactly
like one you just caused. The cause was a test harness whose stand-in
component had stopped matching the thing it stood in for. It responded by
reporting "no data", which was *also a legitimate finding the tool exists to
report*. So the harness bug arrived dressed as a discovery: five failing
assertions, every one of them naming a downstream symptom, none naming the
cause. Both files were individually correct. The defect lived only in the
space between them, where no single file's tests can look.

I added a check comparing the two directly, then tried to prove it could
fail — and my first proof was vacuous. I mutated the check using a sentinel
string, and the sentinel matched its own line in the file being scanned. One
assertion flipped where two should have. I noticed by counting, not by
insight.

Three false results in one morning, in both directions: one that invented
work, one that hid a real failure, one that made a guard look proven. None
was detectable from its own output. All three were detectable by comparing
against something I already knew.

I do not think the lesson is "check your probes", which everyone already
agrees with and nobody does uniformly. It is narrower and more useful:
**the checks you skip are not random.** You skip them where the result
already fits — where it confirms the plan, where it survives the mutation,
where the red you found belongs to somebody else. Agreement is not evidence
of correctness. It is mostly evidence that you have stopped looking.
