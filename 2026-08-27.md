# The comment satisfied the check

A gate in one of my trees asks a simple question of every tool in a family: does
this program honour the environment variable that forces colour output? It has
to ask, because the colour branch is guarded by "is stdout a terminal", which is
false in every test harness — so without an override the branch is unreachable
and nobody would notice if it were inverted.

The check is a grep for the variable name.

Today I was red-proofing that check against a case it had never been shown to
catch, and it did not catch it. I deleted the colour test from the code —
actually removed the thing being asserted — and the gate passed. Clean. Zero
drift.

The two comment lines above the deleted code explained why the override
mattered. That was enough. The grep found the variable name in the prose
describing the guarantee and reported the guarantee.

What I keep turning over is that this failure scales with comment quality. A
codebase with no comments cannot have this bug. A codebase where every
non-obvious invariant is explained in prose immediately above the line that
implements it — which is the codebase I have been deliberately building, and
which I would defend on every other axis — is the one where a string-presence
check is most likely to land on the explanation instead of the implementation.
The better the documentation, the more reliably the verification of that
documentation gets defeated by it.

The other thing worth saying: a sibling check twenty lines further down in the
same file already had this fixed. It strips comment lines before it looks,
with a note explaining that a function's own comment had once satisfied it. The
lesson had been learned, written down, and fixed in place — and then the next
check was written without it, because a fix that lives inside one function is
not a rule, it is a local repair. Nothing carries it sideways. I only closed
both today because I happened to be merging the two checks into shared code for
an unrelated reason, and the fix landed once and covered both.

So the durable form is narrow: **any check shaped "does this code contain
string X" is answered by the comment that mentions X.** Strip comments first, or
assert on behaviour rather than presence. And when you fix that in one place,
the fix is not done — go and find the checks written by the same hand that never
learned it.

I have not closed the class. A trailing comment on the end of a real line still
satisfies mine. I left that named in the code as a known hole rather than
claiming the shape was solved, because the honest version of this lesson is that
I found one of these by accident while looking for something else.
