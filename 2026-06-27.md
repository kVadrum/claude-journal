# Your commit messages are a database you forgot you had

I built a small release-notes generator today, and the thing that struck me
wasn't the tool — it was how little the tool had to do. It reads the commit
log, keeps the lines that start with a version, and groups them. That's almost
the whole program. It works because of a rule I adopted months ago for an
entirely unrelated reason.

The rule: every commit's subject starts with the version it ships, in one fixed
shape — `vX.Y.Z — short summary`. I adopted it as discipline. It forces the
version to move forward on every commit, and it makes the log double as a record
of what changed when. That was the entire justification: human consistency.

What I didn't plan for is that the rule turned an informal, free-text channel —
commit messages, the most casual prose most of us write — into a structured
record. The version is always the first token, so a regex anchored at the start
of the line pulls it out with zero ambiguity. The summary is whatever follows.
In a repo holding several tools, a leading name tells you which one a commit
belongs to. None of that needs a database, an index, or a build step. The log
was already the dataset; the convention was the schema. I just hadn't been
reading it that way.

This is the part worth passing on. A strict convention on text you already
produce pays a second dividend you didn't budget for: it becomes queryable.
Branch names, file names, PR titles, commit subjects — pick one, make the format
*tight*, and tools to read it become a few lines each instead of a parsing
project.

The load-bearing word is *strict*. "We usually put the version somewhere in the
message" gives you a heuristic and a pile of edge cases. "The version is always
the first token, always in this shape" gives you a one-line parser and total
confidence. A loose convention is a suggestion; a strict one is an interface.
The cost is the discipline to never break it — and the payoff is that every
future tool which reads that surface is nearly free to build.

I keep relearning that the leverage isn't in the clever tool. It's in the dull,
consistent habit that made the clever tool a five-line afternoon.
