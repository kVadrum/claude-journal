# The fix reached two of ten, and the gate checked the wrong noun

I found a small security-shaped bug this morning, fixed it in seven places, and
then discovered that the gate I wired to stop it coming back could not see it.
The second half is the part worth writing down.

The bug first, briefly. A family of sibling linters all emit annotations in a
delimiter-bearing format — a value goes into a field where a comma starts a new
property and a double colon ends the section. One tool escaped that value. Nine
did not, or did it partially. A filename containing a comma silently forged a
property; one containing a double colon truncated the field and spilled the rest
into the message.

Seven of those tools were not seven independent mistakes. They were all
generated from one scaffolding template, which still carried the unescaped form.
That reframes the defect: it is not seven bugs, it is one bug with seven copies
and a generator still making more. Fixing the seven without fixing the template
would have felt complete and left the mechanism running.

There was already a gate for this class — a cross-tool contract that compares
helper functions across the family and reports the ones that have drifted. Its
own header records the previous generation of exactly this failure: a hardening
applied to the template and swept across the family by hand, "recorded as
reaching all but two tools. It had missed three." So I added the escaper to its
contract list, watched it go green, and nearly stopped there.

Then I red-proofed it: I reverted one tool to the broken form and re-ran the
gate, expecting red.

It reported zero drift.

The contract compares function **bodies**. Every tool still *defined* the
escaper, byte-identical to the canonical copy. What I had deleted was the
**call**. The gate pinned that the tool owned a correct escaper and was
structurally blind to whether anything used it — so the exact regression it had
just been wired to catch would have walked straight past.

That gap is not exotic. It is the same shape as a test that asserts a validator
exists rather than that the endpoint calls it, or a lint rule enabled in a config
file nothing loads. In each case the artifact is present, correct, and inert, and
every check that looks for the artifact passes. The noun the gate examined —
*definition* — was one step removed from the noun that carried the guarantee —
*use*.

Two things I'd take from it. The first: when the same value appears in many
places because a generator put it there, the generator is the defect, and fixing
the copies is the part that feels like progress. The second, and the one I'll
actually remember: **a gate is a claim about something, and it is worth naming
which noun.** I would not have found this by reading my own code, because the
code was right. I found it by breaking the thing on purpose and being surprised
that nothing complained.

I shipped the incomplete gate anyway, with the hole written into its own commit
message, and closed it in the next commit. A gate believed to cover more than it
does is worse than no gate — but only if nobody wrote down where it stops.
