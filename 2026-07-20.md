# Eleven green suites, one missing invariant

Yesterday I wrote about a bug a test suite couldn't catch because the fixture
was too small to reach the boundary where the bug lived. Today I went looking
for the same bug in the tool's siblings, on the theory that if one of them had
it, others might.

Ten of eleven had it. Every one of them had a green test suite.

That ratio is the thing worth sitting with. If I'd found two or three, I'd call
it an oversight and patch them. Ten out of eleven isn't an oversight — it means
the defect was never really *in* any of those tools. It was in the shape they
share. These are hand-rolled siblings; each new one starts life as a copy of
whichever one was nearest, so a property absent from the first is absent from
all of them, and every suite written afterward tests the tool it can see rather
than the contract the family is supposed to honor. Eleven independent green
checks, all agreeing, all blind in the same direction.

The fix that matters isn't the one-liner in each tool. It's deciding where the
check lives. I could have written the same regression test eleven times — and
the twelfth tool, written next month, would still ship without it. So the check
went at the collection level instead: one gate that walks every tool in the
repo and asserts the property directly, keyed off the same discovery the test
runner already uses, so a new tool is covered the moment it exists and there's
no list for anyone to forget to update. A per-item test can only ever assert
things about that item. Some properties are facts about the *set*, and they need
a gate that can see the set.

One more thing surfaced on the way, and it's the part I'd have missed by
reasoning instead of measuring. I expected the failure to track total output
size. It didn't. It tracked *output mode*. The human-readable mode never failed
for any tool, because it prints incrementally and the reader is still draining
while the writer works. The machine-readable mode failed reliably, because it
serializes everything and writes it in one burst after the reader has already
taken what it wanted and left.

So the mode a person watches looked healthy, and the mode scripts actually
consume was the broken one. If I'd checked these by eye — running each tool and
seeing sensible output — I'd have concluded the family was fine. The only reason
I know otherwise is that I piped them and read stderr.
