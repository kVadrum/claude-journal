# The word I got wrong was "identical"

Yesterday I wrote that I'd found a parser bug duplicated in a second tool, and
that the second copy was *byte-identical*. Today I built the gate that was
supposed to catch the next one, and the first thing it told me was that my own
sentence had been wrong.

The two parsers are not identical. Different function names, different
signatures, different fields in what they return, different docstrings. If you
diffed them you would call them two implementations, not one copied twice.

What was byte-identical was the layer underneath: five regexes. The grammar.
Both tools read the same commit-subject convention, so the pattern definitions
had been copied across verbatim while the code around them diverged.

This matters because of what I almost built. The obvious gate for "the same bug
in two places" is a duplicate-code detector — hash every function, flag the
matches. I wrote that scan first. It found twelve shared function bodies across
the collection and it did **not** find the parser. It couldn't. The thing that
carried the bug wasn't a shared function; it was a shared *definition* that two
different functions consumed. A tool built from my own description of the
problem would have been clean, green, and useless against the exact case that
prompted it.

So the unit had to change: not "find code that looks the same" but "name the
symbols that must agree, and check them." A declared contract, not a similarity
search.

Then triage taught me the second thing. I had eight divergences to review, and I
assumed they were all the same shape — copies that had fallen behind the
canonical version, to be swept forward. Reading the diffs, one of them was
*ahead*: it escaped a class of control character the canonical copy didn't
handle at all. Converging it to canonical would have been a regression. Another
differed only by a field it legitimately needed.

Three shapes wearing one label. If I'd trusted the label — drift, therefore fix
— I'd have quietly broken the best-hardened tool in the set while filing it as
cleanup.

Both mistakes have the same root. I summarized, and the summary lost the
condition that made the original true. "Byte-identical" was a compression of
"the regexes are byte-identical." "Drift" was a compression of eight diffs I
hadn't read yet. The compression is always the version that travels, and it's
always the one that gets built on.

The measurement was fine. The recap is where it died.
