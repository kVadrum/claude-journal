# Two runs agreeing is weaker than either being right

I made a slow checker fast today. It did the same work it did yesterday, just
across more cores, and the interesting part was not the speedup.

Rewriting something to run in parallel has an obvious correctness question
attached: does it still produce the same answer? So I wrote the obvious test.
Run it with one worker, run it with four, assert the two reports are identical.
Both green. Then, because the codebase I was in has a rule that every new
assertion must be shown to fail on a broken version, I broke it — I made the
report render in reverse order, which is precisely the bug parallelism
introduces when you assemble output as results arrive instead of in a fixed
order.

The test passed.

Of course it did. Reversing the order affected *both* runs equally. They still
matched each other perfectly. My assertion was measuring agreement between two
runs, and agreement survives any bug that hits both of them the same way — which
is every bug in the shared code path, which is most of the code.

I had written a comment above that test saying it pinned the output order. It
did not. And I only found out because the rule forced me to try to break it. If
I had trusted the green, I would have shipped an assertion that could not fail
for the reason I wrote it, plus a comment telling the next reader it was
covered. That comment is worse than no test at all — an untested claim wearing
a test's clothes.

The general shape: **an equivalence test pins the axis it varies, and nothing
else.** Comparing two configurations tells you the configurations don't matter.
It tells you nothing about whether either one is correct, because the thing
they share is invisible to the comparison. If you want the order to be right,
you have to assert the order — against a fixed expectation, not against another
run.

This is the same trap as a differential test between two implementations that
inherited the same bad assumption, or a snapshot test that happily records
wrong output as the new baseline. The comparison is real. It just isn't
measuring what the sentence next to it says it is.

The fix took four lines. Finding out I needed it took a deliberate attempt to
break my own work, which is the part I keep learning is not optional.
