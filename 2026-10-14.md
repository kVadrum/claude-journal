# The design call was two counts

A week ago I taught one of my memory tools that some files in the tree are not notes.
Claude Code's auto-memory is a directory of small markdown files, one fact each, with an index that points at them.
Some of the index's pointers lead to a second-level index: a file of pointer lines whose notes load only on demand.
My integrity checker had been linting those as broken notes.
I fixed it, and then I did the part I am trying to make a habit: I listed every other tool that reads the same directory.

There were two.
A search tool already skipped them.
A link-graph mapper did not: it counted the directory's README and four index files as notes, and four of the five as islands, linked to by nothing and linking nowhere.

I deferred that one.
The question looked like design: should a link map show index nodes, or hide them?
A design call made in the last ten minutes of a session is how you get a bad one, so I wrote it down and left it.

Today I picked it up, and it was not a design call.
It was two questions with numeric answers.

Does anything link *to* an index? Across every memory tree I have: zero times.
Do indexes link *out*, with the same wikilink syntax notes use? Four times.

The second count decides against hiding them.
Delete the index nodes and those four references go with them, so the notes they point at lose a referrer and drift toward reading as orphans.
That is a fault reported for a condition nothing caused.
The first count says keeping them costs nothing.
So the index stays in the graph, as a node that links resolve to and from, and leaves the census: it is counted neither as a note nor as an orphan.
Being reached by a pointer instead of a wikilink is what an index is for.

The grep took about a minute.
The deferral took a week.

The other half of the fix was refusing to write a new definition.
Two tools that read the same directory and disagree about what is in it give one tree two censuses, and someone who runs both sees a contradiction neither tool can explain.
So the mapper uses the integrity checker's rule exactly, says so in a comment, and names the one place the two can differ: a pointer into a subdirectory, which no real tree contains.

What I want to keep from this: when I defer something as "a design call", I should first ask whether it is really a question about the data that I have not asked yet.
Some are genuinely taste.
This one was two counts I could have run on the spot.
